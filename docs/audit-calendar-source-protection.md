A historical writer must not ship while an older worker can create a raw-ID duplicate or overwrite a coach's historical outcome. Keep existing unreviewed routine behavior and worker controls; activate additional protection only for explicitly reviewed source decisions. No mass binding/backfill is permitted.

Add private source decisions keyed by studio, canonical calendar ID and event ID, with immutable decision history/receipt support in the subsequent writer. Protected linked lessons must be historical at review time; future booking/student cancellation authority is outside this historical contract and must not be silently restricted. “Not a lesson”, skipped and reopened-for-review decisions also prevent automatic resurrection. Preserve the canonical response ID, never the alias, in source decisions. A failed/malformed metadata or protection read must fail before canonical writes; it must not be interpreted as no protected records.

Read minimal event identity/version/status/time observations in bounded batches; 250 is a batch/page size, never a total cap. Store sanitized idempotent observations of changed or cross-calendar ambiguous sources. Before managed projection, cancellation, raw lookup or creation, a protected event must stop at coach review. No provider notification, credit use or canonical update follows that observation. Unprotected records retain their existing behavior; source-coverage and legacy identity risks remain open.

Add database guards so an older application cannot insert a protected raw-ID duplicate, overwrite a protected historical lesson's schedule/outcome/identity, or silently change the corresponding old import decision. Explicit authenticated/validated coach commands retain their authority; financial-only updates are not blocked by a schedule guard. The subsequent reconciliation writer must provide a private transaction-bound authorization for its own exact import write. Private tables remain RLS-enabled with no client grants; only service-only observation RPCs may be called by workers.

Required proof: actual PostgreSQL roles, raw/qualified/cross-calendar collisions, old worker writes, protected outcome preservation, no ledger/outbox/projection effects, request replay and concurrent review/rescan. Synthetic metadata/provider errors and malformed protection responses must fail closed before any canonical write. Inspect existing worker mocks and update them to implement the new provider/protection contract rather than returning a generic success. All original attendance, replay and signed-worker/fencing tests remain required. No production worker or provider is invoked by these tests.

Rollback retains source decisions/observations/guards. Reverting only the application can make old workers fail on protected records; that is a review hold, never permission to drop the guards. Migration, combined #69 operational health, historical writer/UI, controlled provider acceptance and separate publication approval are release gates. No production configuration, attendance, balance, background-worker flag or historical migration is changed.

Retention compatibility: the existing maintenance function deletes old ignored imports and compacts imported payloads. A new guard alone would make that maintenance transaction fail. The additive migration retains the existing two health/cleanup definitions with only four protected-source exclusions, sharing one private predicate; diagnostics and mutation therefore agree. Existing retention durations and unrelated financial/operational policies are unchanged. Protected evidence is retained without poisoning normal cleanup. No historical migration was edited.
