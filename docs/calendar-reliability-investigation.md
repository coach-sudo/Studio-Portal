## Existing paths and boundaries

Portal booking and lesson commands persist authoritative lesson and participant state in PostgreSQL. Calendar work is claimed by the scheduled worker using a claim token and lesson version. The worker looks up the Google event, checks the claim, then inserts, patches, or deletes as applicable. The finish RPC updates the saved mapping and rejects stale or conflicted acknowledgment. A missing mapped event requires review, so restoring a lesson cannot be assumed to restore the old Google event.

Inbound provider intake is separately gated from outbound Calendar projection. It fetches Calendar events and Gmail booking messages, classifies evidence, and reconciles mapped events or persists import records for review. A managed cancellation can use the lesson state command with outbound queuing disabled to avoid echoing the change. Unmapped, personal, or busy-only events must remain separate from lesson and billing state. Existing Google FreeBusy checks serve the availability path. They do not establish a lesson relationship.

The staged foundations include [discovery #79](https://github.com/coach-sudo/Studio-Portal/pull/79), [Connections preview #80](https://github.com/coach-sudo/Studio-Portal/pull/80), [historical source protection #83](https://github.com/coach-sudo/Studio-Portal/pull/83), and [Release C #89](https://github.com/coach-sudo/Studio-Portal/pull/89). Review their shared migrations and commands against current main before integrating them. None was counted as production behavior.

## Proposed reconciliation contract

1. Persist the provider account, calendar, event or recurring occurrence identity, and observed revision before advancing the calendar cursor. A notification can request a poll. Scheduled polls also recover missed notifications.
2. Resolve an exact existing mapping first. When both lesson and provider changed since their last agreed versions, retain both and require review. Handle a tombstone or restoration against its existing identity and preserve permanent lesson history.
3. Suggest an existing student from authoritative booking references or a unique trusted association. Ambiguous guardian emails, weak name or time evidence, conflicting links, and changed review revisions require coach review. Personal and busy-only rules create availability observations without lesson, credit, or billing effects.
4. Apply decisions through an authorized transaction with a revision precondition, audit record, and idempotent receipt. Repeated requests return the original result. A changed source revision requires a fresh decision.

## Publication gate

The conflict hold is a local migration candidate. This investigation used production metadata and stored results. Direct Google read/write, reconnect, missed-change recovery, and a controlled coach journey remain to be demonstrated on a protected environment. Provider intake reopening also requires the existing controlled Calendar/Gmail fault and successful scheduled-run evidence and separate approval. Use a designated test calendar and normal Google consent with the coach when authorization is required. Production settings, schema, deploy, and provider records were left untouched.
