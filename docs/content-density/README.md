## Validation and limitations

- `npm test`: **502 passed in 84 files**, including seven new interaction tests. The old duplicate-heading assertion now checks the accessible Notes region. JSDOM emits its existing canvas-not-implemented notices.
- `npm run typecheck`, `npm run lint`, `npm run check:secrets`: pass. Lint reports 633 warnings and zero errors; this task does not perform a repository-wide warning cleanup.
- `npm run format:check`: passes after normalizing the Windows checkout's CRLF copies of its 12 fixed baseline files to LF. Their committed content remains unchanged; changed application files and new artifacts are formatted.
- Production-shaped `npm run build` and `npm run bundle:check -- --require-configured-client`: pass with the CI placeholder client configuration. Existing CSS gzip warning remains: 23,085 bytes against a 22 KB warning / 25 KB failure budget. No stylesheet changed.
- Matched browser review: 24 views per revision, no horizontal overflow. [Before report](evidence/before/report.json) and [after report](evidence/after/report.json) show the same pre-existing notification-badge color-contrast finding on the workspace and Campaigns; no new serious/critical axe findings on those matched views.
- **90 demo browser checks pass**, covering nine interaction states plus 21 additional portal/settings views at each size. They verify native Enter/Space disclosure, complete notes, note search/dialogs, Add student focus containment/return, campaign unknown-field errors and review, and unchanged financial/removal warnings. No page overflow or clipped controls were found after scrolling each control into view; native text-field scrolling and the existing horizontally scrolling mobile tabs remain available. The [interaction/layout report](evidence/interactions/report.json) includes axe results; warnings are retained rather than represented as a clean accessibility audit.
- Authenticated browser journeys are **blocked locally**: Docker and an isolated authenticated fixture stack are unavailable. Demo checks do not establish live authentication, authorization, delivery, provider, or payment correctness. Existing relevant unit/contract tests pass; the repository's PR CI can run its existing ephemeral authenticated suite.
- No merge, publication, or production deployment was performed. The draft PR is the handoff for review; screenshots and tests do not claim a production rollout.

Reproduce visual evidence with an unconfigured local demo Vite server on `127.0.0.1:5174`, then run `node scripts/review-content-density.mjs after` and `node scripts/check-content-interactions.mjs`. Baseline images were captured before application edits; to regenerate them, use the pinned baseline with the same capture script. `CONTENT_REVIEW_URL` can select a different local demo port. Reports and screenshots are written under `test-results/content-density/`; retained review evidence is copied here explicitly.
