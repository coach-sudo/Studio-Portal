The coach shell's identity query is for branding/identity. Under V2 it intentionally does **not** contain coach students or activity collections. The global notification bell previously built its feed from that partial snapshot. It now makes one authenticated browser/RLS aggregate activity read (I S L B W M D), without signing asset URLs that the feed does not use. After a route mutation, `invalidateStudioDomains` reuses the freshly refetched active domain snapshots to update the activity cache without a third mutation refetch. The portal bell uses the same pattern with the portal role. This adds one initial aggregate RPC; it does not send a service-role credential to the browser. Receipt persistence remains its existing RLS-protected query.

The visible-inbox Realtime callback also uses the targeted messaging invalidation helper. This keeps the global notification feed in sync with an incoming message while refetching only the active messaging domain, not the aggregate activity RPC. A focused query test checks both the visible message and the single refetch.

The full deployed-suite failure on the main-targeted PR was not caused by application code: `USE_EPHEMERAL_STACK` omitted `main`, so the suite targeted a Netlify Deploy Preview whose Function did not have `SUPABASE_URL` after production variables were correctly restricted to Production. The workflow now selects the existing free ephemeral Supabase + offline Netlify preview for main-targeted PRs, generates a run-local fixture token, and keeps the normal Netlify preview smoke check separate. Production-scoped Netlify credentials are not copied to any preview. The existing exact fixture-cleanup comparison remains mandatory for the ephemeral run.
