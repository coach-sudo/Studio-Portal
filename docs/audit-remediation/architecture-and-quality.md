# Architecture and code-quality changes

## Worker observations (SP-01/14)

The existing signed dispatch, service-only enqueue/claim/finish RPCs, 20-minute lease and fencing remain. An additive private RLS table captures queued, claimed and terminal transitions plus allowlisted source-stage observations. Observation RPCs validate the current token before writing stage outcomes. Existing saved terminal receipts are copied with their original timestamps; overwritten history cannot be reconstructed. No provider bodies, tokens, student identities or raw errors are recorded.

The coach-authenticated health endpoint now reads those fixed-shape receipts rather than inferring worker health from the studio query. Disabled configuration wins over an earlier success; queued dispatch, accepted dispatch, running, completed, failed and partial work have distinct meanings. A successful source stage cannot hide a failed second stage. The Settings action follows receipt outcomes instead of declaring processing successful after a 15-second timeout. The polling interval controls read frequency only.

The adapter used by older service commands is retained intentionally. No migration history, financial trigger, role permission, publication control or compatibility route was removed. Provider processing remains idempotent/retryable under its existing command protections; this PR does not claim live provider success or fix the historical Gmail incident.

## Remaining investigations

Manual scheduling now has a focused authoritative transaction/receipt/intent command in draft #71. Paid state follows its checked append-only payment, not an unchecked parallel write; notification failure cannot delete canonical records. Immutable request hashing and actor/key serialization prevent conflicting replay. The client reuses the same key and request after a lost response, before another conflict preview can mistake its own committed lesson for a conflict. The old independent write chain and compensating deletes were removed. The exclusion constraint remains authoritative; Google-only override never defeats local concurrency protection.

Draft #73 shares explicit zoned input formatting/parsing with rescheduling. It rejects nonexistent DST times and requires a repeated-hour choice. Historical creation uses explicit outcome/financial treatment; record-only history consumes no credits and creates no provider or notification intent. Original creation timestamps remain actual recording timestamps. Existing-record correction policy is approved for draft implementation in decisions.md; it is not implemented yet.

Draft #74 removes elapsed-time completion inference from the reviewed SQL command and both automatic source creation paths. Calendar source collisions now fail without upserting existing attendance or deleting participants. Existing reviewed links remain authoritative. Intake's broader nontransactional automatic write chains, historical suppression, one-calendar identity and source coverage remain debt requiring focused discovery/reconciliation work.

Draft #75 extracts positive installment settlement to a service-only invoice-ID transaction with durable recovery effects. Same invoice/different event cannot increment money twice. Checked acknowledgement errors remain retryable. Provider rounding has a stable identity and an unknown-outcome hold beyond the safe retry window; cancellation checks external state. Existing partial financial history is held for reconciliation and is never rewritten. Other Stripe branches, initial invitation recovery, checkout/credit reversal/expiration and payer identity still require fault investigation.

Draft #72 makes the seven original booking tests explicit about timezone and removes ignored diagnostic output from test discovery. It preserves all 1,005 original New York tests. Draft #76 narrows advisory patches to compatible Vite/Vitest lines instead of importing the major toolchain changes in Dependabot #59. Runtime exposure is distinct from development-server advisories.

History is stored append-only and read through a bounded recent-attempt summary with an indexed last-success aggregate. It currently grows with scheduled attempts; retention/archive policy requires operational review. No arbitrary cap is applied to canonical lesson or financial histories. No measured application performance improvement is claimed by this change.

Intentional compatibility retained: public/student booking restrictions, occurrence and review receipt wrappers, current financial constraints, legacy notification adapters, source links, historical migrations and existing publication/CI controls. No adapter was removed merely because it looked old. Remaining debt includes route-history cursor pagination with authoritative totals, timezone fallbacks in provider parsing, duplicate legacy command branches, warning inventory and unverified restore/delivery paths. No repository-wide cleanup or performance improvement is claimed without evidence.
