# Calendar discovery and historical reconciliation plan (SP-10/11/12)

Scope before implementation: C01/C02/C03/C04/C06/C07, B04/B10, D03/D05/D06 and X03/X04/X05/X08/X18/X19/X20. Dependency: #74 attendance separation; #69 operational reporting must distinguish preview completion from canonical import. Preserve signed dispatch, disabled production workers and existing routine intake policy. No provider scan is run against a hosted account during implementation.

This draft implements only the discovery database/API contract. Its dependent interface and historical reconciliation command remain required. It does not claim SP-10/11/12 fully resolved. API reads require a coach and an explicit `GOOGLE_DISCOVERY_STUDIO_ID` binding to the current studio before global Google credentials can be used. That setting is not configured by this work. Saved previews remain coach-readable without a provider connection. Missing/expired authorization, provider throttling/outage, invalid pagination and an unconfirmed database checkpoint have distinct sanitized guidance; no provider payload or token is exposed.

Implement independent coach-authorized preview first. It reads selected accessible calendars and explicit UTC bounds derived from a displayed IANA timezone; it does not import, send mail, create meetings or allocate money/credits. List accessible calendars with pagination and access roles, distinguish configured routine calendar from selected preview coverage, and persist the exact selection/range. Process one bounded provider page at a time with durable progress, per-calendar outcome, request/receipt identity and fenced lease. Page size is a work unit, never a total cap. Explicit continuation must remain possible until all provider pages complete. Partial failure preserves successful calendars/pages and supports a safe retry.

Persist minimal source observations in a private schema. Use calendar ID plus event ID, series/original occurrence identity, etag/update and cancellation state; never treat event ID or iCalUID alone as a cross-calendar occurrence. Explicitly show date-only/all-day entries requiring a coach-provided time, insufficient identity, non-lesson classification and unsupported/deleted states. Detection is not attendance. Keep prior ignored/reviewed imports and possibly linked lessons visible without reopening them automatically. Preview stores no provider token, raw email body or unrestricted provider response.

Actual contract: immutable scan selection/range and hashed start identity, per-calendar page sequence/cursor, two-minute fenced processing lease, durable page receipts and append-only success/failure observations. Each request reads at most 250 minimal-field events, including recurring occurrences/exceptions and cancellation tombstones. An empty page with a continuation is not completion. Equal IDs from different calendars have different source keys. Candidate and saved-scan reads return 25 rows plus explicit cursors and authoritative totals. A selection batch accepts 1–100 calendars as a request-size bound; it is not a hidden event/history cap. There is no historical date cutoff. Legacy unscoped source matches are explicitly possible matches, not confirmed links. No legacy worker or provider review behavior is changed.

Historical reconciliation is a separate reviewed transaction: reopen one selected ignored signal with reason; link an exact existing lesson/version; create an explicitly scheduled historical record; not a lesson; or skip with reason. Before creating, lock studio/student/source identity and find linked/possible duplicates, including cancelled records. A date-only entry requires an explicit timezone-aware interval. Existing attendance, ledger and creation timestamps survive linking. Historical create queues no Calendar projection, notification or automatic coverage; explicit completion must be a separate attendance command. Durable request hashing rejects changed-payload replay. Financial consequences use existing explicit finance commands; no new settlement policy is introduced.

Gmail coverage must state the current 90-day keyword filter and exclusions; use explicit Unix seconds for reviewed date bounds, because Gmail date-only search bounds use Pacific time. A deliberately submitted message ID or reviewed search may produce a candidate, never automatic arbitrary-email lesson classification. Scope failures remain distinct from malformed payload, throttling and provider outage.

Rollback retains observations, selections, decisions and receipts; it must not resurrect ignored candidates or erase links. Required gates: multi-calendar ID collision; >250 events and empty page with continuation; recurrence exception/cancelled tombstone without dates; date-only/timezone conversion; historical/ignored/linked preview; repeated/concurrent/rejected replay; stale lease/provider response/lost response; partial 403/429/5xx/timeout; exact role isolation in PostgreSQL; no financial or outbound effects; Chromium/WebKit keyboard/axe/responsive screenshots; real restricted test-calendar acceptance explicitly pending.
