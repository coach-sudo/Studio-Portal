# Identity-preserving duplicate profiles — FIN-R02

Implementation scope recorded before code, October 28. The user approved the identity-preserving design in [decisions](audit-remediation/decisions.md) for draft implementation only. This independent contract draft follows operational branch #69; it does not include historical Calendar commands. A separate focused coach interface is required before release.

Affected acceptance: A02/A03/A04, D01–D06 preservation, E02/E03 private teaching work, F06/F07 and X10/X16/X17/X20. The existing physical merge can fail on a recovery-job foreign key and also transfers dependent identities. Replace that public mutation with actionable review guidance; keep its historical implementation private for compatibility investigation. Never call it from the new command.

Store an audited identity group and active profile memberships privately. Retain original student IDs, accounts, invoices, immutable receipts, source links, notifications, resources, private notes and per-record guardian/student permissions. Current-profile selection controls coach navigation only. New scheduling must still select an exact student. No account, Stripe customer, guardian entitlement or balance is combined or transferred. Membership alone grants no access. Different authenticated users, guardian/payer identities and external customer identities require explicit review; unsupported identity collisions remain blocked.

Preview and commit require an authenticated studio coach, an explicit reason, a sealed identity/dependency stamp and a durable actor/key/request-hash receipt. Authorize before replay. Serialize competing groups and exact profiles, recheck stale previews, then atomically write group/membership revision, audit and receipt. Failed audit/receipt writes roll back the grouping. Reversal is a new audited action retaining historical group membership and receipts; it does not undo intervening scheduling or financial work. Never physically delete a profile or invoke external effects.

Validation must cover actual PostgreSQL roles, independent linked-record access, retained financial/recovery/source/private-note records, no guardian privilege union, conflicting external identities, stale previews, replay/lost response, concurrent grouping, late write faults and audited reversal. Cursor-based group reads must expose authoritative totals. Existing physical-merge tests will explicitly assert the approved review hold and preservation, with original reproductions retained in the audit evidence rather than relabeled as passing merges.

Rollback leaves groups, memberships, revisions and receipts intact; disable new commands/interface if needed. Do not restore the legacy destructive public command once grouping is accepted. No production merge, migration, identity mutation, worker change, provider call or publication is authorized. This plan is not implementation or acceptance evidence.
